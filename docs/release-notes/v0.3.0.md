Seventy-one commits since `v0.2.0`. `0.2.0` was tagged and never published, so this release is the first version the registry serves since `0.1.1`, and it names the same tree as `main`.

Install: `npm install -g pi-superagent@0.3.0`

## Capacity and priority

- Label an ask `priority:high` and it wins the next free worker slot; the launch lane follows the board label, and a labelled launch queues down the lane instead of jumping it.
- Adoption takes a slot, so a router restart can no longer run past the worker cap.
- A labelled ask gets six relaunches a day, and the regrant cap is now a setting that logs the budget it refused.
- Intake asks a quiet issue when a slot is free, so idle capacity reaches ready work instead of idling.
- A worker whose own background task woke its session is no longer treated as a silent worker.

## Pull requests, checks, and endings

- A ticket waiting on CI is woken when its checks finish, and is told that — not the clock — is what wakes it; the running build is stored so the router can say so.
- A ticket on a pull request in another repository ends when that pull request closes.
- A ticket waiting on a pull request nobody in the fleet can close stops, and the closer asks GitHub per pull request rather than trusting a stored answer.
- **A pull request this account can never read is now said on the ticket, once, naming the one grant that fixes it — and a closing receipt can no longer report an outcome the router never saw.** Measured: 24 unreadable reads in a day, and a board issue closed with "closed without merging" about a pull request that merged.

## Panel

- Serve it behind a reverse proxy with a token required on every request.
- Read and type into a worker's terminal from the browser; the page says who is asking, shows worker screens, and puts a stop button on every ticket.

## Disk pressure

- Under pressure the router clears shared caches first (only above 2 GB) and stops launching. Worktrees that hold work survive, unpushed commits get asked about before a checkout goes, a clone another workspace borrows git objects from never gets deleted, a parked worker's venv goes only when nothing runs in its workspace, worker scratch moves to its workspace, a nearly full `/tmp` gets swept, and a truncated cursor no longer breaks the pass.

## Safety, privacy, speech

- Pasted credentials get masked on the way in, not only on the way out.
- `Redacted` identifiers get scrubbed from the tree the package ships.
- The first post publishes in blocks, so it stops rendering as one run-on paragraph. A capped thread gets refused once a day, not once a poll.

## Reliability

- A judge that stops deciding gets probed, reaped, and announced.
- `restart` proves the engine stopped, and `status` reports engine and tab apart.
- The sweep reclaims work-root scratch that had been warning `worktree.strays` forever; `ticket_decide` now fails when its eval is already gone.

## Release engineering

- CI runs on every push and pull request: type-check plus the suite. A log-race flake that cost a worker slot is fixed.
- Publishing moved to CI. A tag push runs the checks a runner can prove, installs the packed tarball into a throwaway prefix, runs the shipped command through the symlink npm leaves and refuses an empty answer, publishes with provenance, and opens this page. `npm publish` by hand aborts in `prepublishOnly`, because the packed check starts a real engine and needs a runner that has one.
- The package manifest pins the publish target to the public registry with public access and provenance, so a machine whose default registry is a corporate mirror cannot receive a publish by accident.

## Known limitation

62 tests skip on Linux: the two suites that start a real router against a real panel pass only where a router can start on the runner, and they fail on a box that already runs one. The measurement and the diagnosis are on https://github.com/kmatzen/pi-superagent/issues/160; every run reports them as named skips rather than as silent passes.
